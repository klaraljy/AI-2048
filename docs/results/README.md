# 基线结果

> 每次算法或规则改动后的跑批结果都归档在这里。
> **每个结果必须带规则集版本与种子集版本** —— 否则分数不可比。

## 怎么读这些数字

- **平均分**才是判据，**单局最高分不算数**。2048 的随机性很大，
  单局高分说明不了任何问题。
- 到达率一栏是"有多少局的最大块达到过这个值"。
- 换了规则集或换了种子集，就**不能**和下面的数字比。

## M1 — 引擎基线（平凡策略）

**这不是 AI 的表现，是引擎正确性的证据。**

里程碑 1 的走子策略是刻意平凡的：按固定顺序取第一个合法方向。
它的存在意义是让一局能跑到终局，从而验证走子 / 合并 / 生成 / 终局判定整条链路。
真正的 AI 属于里程碑 2。

| 项 | 值 |
|---|---|
| 规则集版本 | 1 |
| 种子集 | `seeds-v1.txt`（1..100）与 `seeds-1000-v1.txt`（1..1000） |
| 标记 | `M1-trivial-policy-baseline` |
| 日期 | 里程碑 1 完成时 |

### 1000 局

```
局数       : 1000
平均分     : 2309
分数区间   : 288 .. 6788
平均步数   : 208
平均每局   : 1 ms
总耗时     : 0.051 s（12 线程）
到达率     : 128=87%  256=49%  512=2%  1024=0%
```

### 100 局

```
局数       : 100
平均分     : 2283
分数区间   : 360 .. 5484
平均步数   : 207
到达率     : 128=87%  256=48%  512=2%  1024=0%
```

### 从这组数字能读出什么

- **平凡策略大约到 256 就结束**，平均 200 多步。这符合预期。
- **两档种子集的到达率高度一致**（87%/87%、48%/49%），说明 100 局那档的
  抽样已经足够稳定，可以作为日常迭代的判据。
- **每局 1 ms** —— 引擎本身的开销可以忽略，里程碑 2 之后耗时将完全由搜索主导。

### 确定性

```
selfcheck（100 局）  : 通过，逐字节一致
selfcheck（1000 局） : 通过，逐字节一致
```

另外单元测试里有与 Cirulli 原始算法在**全部 65536 种行状态**上的逐行对拍，
左右两个方向完全一致 —— 这是规则正确性的主要依据。

## 结果归档格式（约定）

**还没实现自动归档**（里程碑 5）。在那之前，人工往这里追加，格式如下：

```markdown
## M<n> — <一句话说明>

| 项 | 值 |
|---|---|
| 规则集版本 | <RulesetVersion()> |
| 种子集 | <文件名> |
| 标记 | <--tag 的值，只用 ASCII> |
| 改动前的平均分 | <数字> |
| 改动后的平均分 | <数字> |
| 结论 | 留下 / 回退，理由 |
```

> ⚠️ `--tag` 只能用 **ASCII** 字符。Windows 的命令行参数走 ANSI 代码页而不是
> UTF-8，中文会变成乱码，而 tag 会被写进归档文件名。CLI 会直接拒绝非 ASCII 的 tag。
