# 评估函数标定探针

两个临时性的诊断程序，用来回答一个具体问题：

> **本项目的评估函数实际上是被哪些项左右的？**

它们**不参与构建、不被测试引用**，需要时手动编译（下面的命令）。
之所以放进版本库而不是留在 `_tmp`：评估函数的标定是反复要做的事，
而这两个探针给出的结论（见 `AGENTS.md` 的「评估函数的决策权重」一节）
是调参的**前提**——不知道谁在说话，调参就是盲调。

## 为什么需要它们

权重（`empty = 400`、`monotonicity = 250`、`corner = 2200` …）只有在
**各项的原始量级可比**时，才谈得上"相对重要性"。而实测各项的原始量级差了
**两个数量级**（`smoothness` 平均 36、`merge` 平均 1.3），所以那些权重数字
排出来的优先级是**偶然的，不是设计出来的**。

## 两个探针的区别（这个区别很重要）

| 探针 | 度量 | 回答的问题 |
|---|---|---|
| `magnitude_probe` | 各项的**绝对量级** | 谁在决定总分的大小 |
| `influence_probe` | 同一局面下**各候选走子之间**该项取值的 (max−min) | **谁在决定走子** |

**只有第二个能回答"谁在左右决策"。** 一项的绝对量级再大，如果它在所有候选
走子上取值都差不多，那它只是个常数偏移，对选择毫无影响 —— 这正是
`empty` 与 `snake` 的情况（占了 68% 的绝对量级、却几乎不区分走子）。

`influence_probe` 输出的 **散布/|均值|** 一列尤其有用：它是"区分度"的度量。
区分度高 + 权重低 = 被浪费的信号（`merge` 就是这么被找出来的）。

## 编译与运行

```powershell
$root = 'engine'
$gxx  = 'D:\Codex Tools\Tools\mingw1310_64\bin\g++.exe'
# 需要先构建一次引擎（用其中的 libai2048_core.a）
& $gxx -std=c++20 -O2 -I"$root\include" -I"$root\src" `
  tools\calibration\influence_probe.cpp "$root\build\libai2048_core.a" `
  -o "$env:TEMP\influence.exe"
& "$env:TEMP\influence.exe" 4 2      # 参数：深度 局数
```

`magnitude_probe` 用法相同。两个都只跑几秒到几十秒，**不消耗对拍预算**。

## 注意

- 输出依赖当时的 `Weights` 默认值 —— 改了权重就重跑一遍再下结论。
- 探针里的 `W_*` 行是"加权后的贡献"，除以对应权重就是原始量级；
  权重为 0 的项（`edge_support` / `gradient` / `mobility` / `islands`）
  还原时会得到 `nan`，属预期，不是错误。
