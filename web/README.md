# 前端（桌面浏览器 / WebView）

**状态：里程碑 3 已完成。** 原生 HTML / CSS / JS，**零依赖、零构建步骤**。

刻意不引框架：交互量很小，而加 Vue 会带来构建链、依赖升级、
以及"手机上还要额外打包"的负担，收益不成比例。

## 怎么跑

```sh
# 任选一个静态服务器（ES module 在 file:// 下会被拦，必须走 HTTP）
npx serve web

# 想连 C++ 引擎（里程碑 4 之后才有服务）：
#   http://127.0.0.1:8080/?engine=ws://127.0.0.1:8765
# 不传 engine 参数就用本地降级 AI。
```

## 模块

| 文件 | 职责 |
|---|---|
| `js/rng.js` | xoshiro256\*\* + splitmix64 + Lemire 拒绝采样，用 BigInt 做 64 位运算 |
| `js/game.js` | 规则引擎。**与 C++ 引擎逐位一致**，由 `tests/parity.test.mjs` 保证 |
| `js/renderer.js` | 渲染与动画。方块有持久 id 与独立 DOM 节点，绝对定位靠 transform 滑动 |
| `js/input.js` | 键盘 / 触屏滑动 / 输入锁 |
| `js/sound.js` | WebAudio **现场合成**音效，不引入任何音频文件 |
| `js/transport.js` | AI 决策来源。**唯一**知道"怎么拿到决策"的文件 |
| `js/main.js` | 装配层，只做编排 |

## 三条硬要求的落实

**1. 不得内联 AI 逻辑。** 玩家走子用 `game.js`（那是规则，不是 AI）；
AI 决策一律走 `transport.js`。

**2. 传输层可换。** `createTransport()` 返回 `{transport, degraded, reason}`：

- 配了 `?engine=` 且连得上 → `WebSocketTransport`（C++ 引擎）
- 连不上或没配 → `LocalTransport`（本地贪心，**很弱**）

降级时页面顶部**显示明确提示** —— 不能让用户以为降级 AI 就是引擎的水平。
这条是刻意的：把"降级"藏起来比降级本身更糟。

**3. 引擎连不上不白屏。** 降级路径就是上面第 2 条，页面照常可玩。

## 关键设计：为什么滑动动画能实现

参考原型每步 `innerHTML = ""` 重建 16 个节点 —— 方块没有身份，
也就没有"上一帧位置"，**滑动动画在那层结构下不可能实现**。

这里是相反的：

```
每个方块一个持久 id + 一个独立 DOM 节点
方块绝对定位在 .tiles 层，靠 CSS transform 移动（transition 生效 → 平滑滑动）
一次走子按顺序演：滑动 → 合并弹跳 + 换值 → 删掉被吸收的块 → 新块缩放淡入
```

`renderer.js` 还维护"逻辑状态 ↔ 棋盘"的一致性，`tests\renderer.test.mjs`
会在连续 120 步走子后逐格核对两者相符、且 DOM 节点数没有泄漏。

## 输入锁

动画约 250ms，期间如果再来一次走子，逻辑已推进但画面还在演上一步。

**处理方式是丢弃输入，不是排队** —— 排队会让快速连按积累出一长串延迟动作。

锁必须是**查询式**的（`isLocked` 回调）。早期实现用一个布尔量由外部手动同步，
结果动画结束后没人解锁，**第一次走子之后键盘就永久失效**。
`tests\input.test.mjs` 里有这条的回归测试。

## 已知限制

- **本地降级 AI 很弱**（贪心启发式，几千分水平）。要强 AI 必须连引擎。
- 音效需要**首次用户手势**才能解锁（浏览器 autoplay 策略），
  这是浏览器限制，不是缺陷。
- 视觉与手感**没有自动化测试**：`tests\` 覆盖逻辑与状态一致性，
  "是否平滑好看"只能人工走 `../AGENTS.md` 的验收清单。
- 尚未接引擎（等里程碑 4 的服务）；`transport.js` 的 WebSocket 实现已写好但没实测过。
